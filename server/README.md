# 共有商品データベース

公開先を固定しない、Node.js 24.19以降 + SQLite の独立したAPIです。現段階ではローカルで動かし、公開URLが決まったらアプリの接続先を設定します。

## 共有範囲と画面の流れ

- 外部検索でも見つからなかったJAN/EAN商品を手入力したとき、共有のチェック項目を表示します。初期状態はオフです。
- 送信前に、バーコード・商品名・レシピ用分類・カテゴリの4項目を確認できます。
- 在庫、数量、単位、期限、購入日、保存場所、メモ、写真、タグ、利用者IDは共有しません。APIも余分なフィールドを拒否します。商品名や分類にも個人情報を入力しないでください。
- 個人の食材は従来どおり端末内に保存します。共有の通信失敗時には完了画面から商品情報だけを再送できます。自動送信キューはありません。
- 検索順は、端末で学習した商品 → サンプル → 共有DB → Yahoo!ショッピング → Open Food Facts。共有APIの障害時も外部検索へ進みます。
- 共有商品を利用する人の保存場所や数量・期限は、その人の登録画面で決定します。投稿者の設定は引き継ぎません。
- 共有対象はチェックデジットが正しい8桁・13桁のJAN/EANです。2で始まる店舗用コードやUPC-Eなどは対象外です。外部サービスで取得した情報の再投稿も行いません。

## ローカルで動かす（PowerShell）

リポジトリ直下で実行します。APIには追加のnpmパッケージは不要です。

```powershell
npm run shared-api
```

別のターミナルで、`.env.local` に次を設定してExpoを起動してください。既存ファイルがあればこの項目のみを追加・変更します。

```dotenv
EXPO_PUBLIC_SHARED_PRODUCTS_URL=http://127.0.0.1:8787
```

```powershell
npm run web
```

APIは初期状態で同じPCからのみ接続できます。DBは `server/data/products.sqlite` に自動作成し、再起動後も残ります。このフォルダーと `.env.local` はGit対象外です。URL未設定でも食材登録・従来の商品検索は動作します。

スマートフォン上のlocalhostはスマートフォン自身です。実機から利用するときは、信頼できるHTTPSのAPIを設定してください。アプリはローカルホスト以外の平文HTTP接続を許可しません。

## 公開先が決まったら

Node.js 24.19以降の実行環境に `server/` と `shared/` を配置し、`node server/start.cjs` をリポジトリ直下相当のディレクトリから起動します。データベース用の永続ディスクを用意してください。アプリとは別に配置できます。

| 環境変数 | 初期値 | 用途 |
| --- | --- | --- |
| `SHARED_HOST` | `127.0.0.1` | API待受先。コンテナで必要な場合は `0.0.0.0` |
| `SHARED_PORT` | `8787` | APIポート |
| `SHARED_DB_PATH` | `server/data/products.sqlite` | 永続ディスク上のSQLiteファイル。絶対パス推奨 |
| `SHARED_ALLOWED_ORIGINS` | `http://localhost:8081,http://127.0.0.1:8081` | 許可するWebアプリのオリジン。カンマ区切り、ワイルドカードなし |
| `EXPO_PUBLIC_SHARED_PRODUCTS_URL` | 未設定 | アプリに埋め込むHTTPSのAPIベースURL |

APIの前段でHTTPS終端とアクセス制限を設定し、Webアプリの実際のオリジンを許可します。アプリ側の環境変数を変更したらExpoを再起動し、配布アプリは再ビルド・再配布してください。`EXPO_PUBLIC_` の値は公開されるため、DBの認証情報や秘密鍵は入れません。

## API

`POST /v1/products` に `Content-Type: application/json` で送信します。

```json
{
  "barcode": "4901234567887",
  "name": "共有テスト牛乳",
  "ingredientName": "牛乳",
  "category": "dairy"
}
```

商品名は120文字以内、分類は60文字以内。改行・制御文字は不可です。カテゴリは `vegetables`, `meat`, `seafood`, `dairy`, `eggs`, `staples`, `seasonings`, `beverages`, `other` のいずれかです。

| 応答 | 意味 |
| --- | --- |
| 201 `created` | 新規保存 |
| 200 `already_shared` | 同じ4項目が保存済み。再送成功 |
| 409 `already_exists` | 同じバーコードの内容が異なる、または管理者が非表示化済み。上書きしない |
| 400 / 413 / 415 | 不正データ / 2KB超過 / JSON以外 |
| 429 | 投稿・検索の回数制限 |
| 503 `catalog_full` | 保存上限 |

`GET /v1/products/:barcode` は `{ "product": { ...4項目 } }`、未登録・非表示の場合は404を返します。`GET /health` は稼働確認用です。

## 管理・運用

初期実装は匿名投稿を受け付ける単一インスタンス向けです。ログイン、投稿者の信用評価、通報画面、自動審査は含めていません。CORSは認証の代わりにはなりません。公開運用では、前段の投稿制限・監視と、不正な商品情報を管理者が対応する運用を用意してください。

APIは接続元ごとに投稿20回/時、検索300回/分、最大5万商品に制限します。IPはソルト付きハッシュをプロセス内の短期カウンターにだけ使用し、DBやアプリログには保存しません。カウンターは再起動でリセットされます。リバースプロキシ経由では接続元が共通になるため、前段でも適切な制限を設定してください。`X-Forwarded-For` は信用しません。ホスティング側のアクセスログは別途設定が必要です。

誤情報はサーバー管理権限のある端末から非表示化・復元できます。同じ `SHARED_DB_PATH` を指定して実行してください。公開の管理APIはありません。

```powershell
node server/admin.cjs hide 4901234567887
node server/admin.cjs restore 4901234567887
```

公開APIでは既存商品を変更・削除できません。内容訂正は管理者がバックアップ後にDBを整備する運用です。非表示の商品を同じバーコードで再投稿しても復活しません。

DBのバックアップはAPIを停止してから `products.sqlite` と残っている `-wal` / `-shm` を一式保存してください。稼働中に本体ファイルだけコピーしないでください。複数インスタンスに拡張する場合は共有DBへの移行と投稿制限の共通化が必要です。

## 検証

```powershell
npm test
npm run typecheck
```

テストは一時DBで、別クライアントからの参照、再起動後の永続性、個人項目の拒否、重複投稿、通信障害時のフォールバック、共有同意、再試行時の食材重複防止を確認します。テストデータを運用DBへ流し込む必要はありません。
