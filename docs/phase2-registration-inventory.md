# Phase 2：登録と在庫計算の整合性

2026-09-29実装。監査のA4・B3・B4・B5・C3・C9を対象とする。利用手順は[使い方ガイド](USAGE.md)を参照。

## 在庫の使用記録

- 分量判定と調理画面が同じ在庫一覧を使い、期限順に使用量を割り当てる。期限切れ・使用済み・廃棄済みを除外する。
- 数量を比較でき、合計が必要量を満たす場合だけ自動選択する。別単位や複数材料で重複照合する在庫、分量不足は推測しない。
- 確認画面の数量・単位・期限・更新番号を最新の在庫と照合する。一件でも変更されていれば全件を中止する。
- `recordConsumption` は最新の在庫を一度に更新する。減算と操作ID付きの在庫別履歴を同じ保存値に含め、同じ操作IDの再実行を無視する。
- 一般的な食材編集は使用履歴や状態を上書きしない。使い切った在庫は既存の取消操作のため最後の正数残量を保持し、状態を`used`、使用履歴の残量を0にする。
- 保存失敗の表示・再試行はPhase 1の共通処理を利用する。ディスク保存前の強制終了については実機検証が必要。

## 商品登録・訂正

- 登録・編集時に商品名と表示名をそろえる。バーコードを在庫の独立した項目として保持する。
- 旧形式のメモが正確に`バーコード: 数字8〜14桁`の場合だけコードを引き継ぐ。既存の分類・数量・期限は自動変更しない。
- 商品訂正は商品名・レシピ用分類・カテゴリのみを端末の商品候補へ反映する。今回の個人在庫情報を共有APIへ送らない。
- 学習商品はPhase 1の直列読み書きを利用し、同時保存による消失を防ぐ。候補更新に失敗しても在庫編集は維持し、再試行または候補更新なしの保存を選べる。
- 焼きそば麺、米酢、米粉、プリン、サラダチキン、炊飯済みごはんを原材料と区別する。複数の分類が競合する商品は商品名を残し、利用者の確認を求める。
- Yahoo!ショッピングとOpen Food Factsは共通ルールから保存場所を提案する。外部検索由来の保存場所を取得済みの確定値として扱わない。

## 検証

- 自動テスト134件、TypeScript型チェック成功。
- 牛乳100＋200mlから200ml使用、複数在庫表示、単位混在、人数変更、分量不足、期限順、古い確認操作の中止、連打、再起動・バックアップ復元後の重複防止を検証。
- 商品名訂正、候補更新の失敗・再試行・選択解除、次回検索、同時商品保存、個人在庫情報の除外、旧メモの移行、取得元ごとの分類・保存場所を検証。
- iOS・Android向けJavaScript書き出し成功（`--no-bytecode`）。ネイティブビルドやスマートフォン実機での動作確認ではない。
- Webで既存在庫を読み込み、使用量0.25個→使用後0.75個のプレビュー表示を確認。実在庫への調理確定は行っていない。

実機のカメラ読み取り・通信・保存失敗時の挙動は引き続き実機確認が必要。共有商品DBの訂正・公開・管理機能はこの変更の対象に含めない。
