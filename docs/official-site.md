## 手元で起動する

Node 24.19以降の24系と、このリポジトリの依存が必要です。

```powershell
npm.cmd run site:dev
```

`http://127.0.0.1:8105/index.html` を開きます。PC内だけの確認用です。Ctrl+Cで停止します。ポートが使用中なら先の表示用サーバーを停止するか、次を使ってください。

```powershell
npm.cmd run site:dev -- --port=8107
```

編集後は停止して再実行し、ブラウザーを再読み込みします。自動監視・自動更新はありません。CSS・JavaScript・画像のURLには内容に応じた版が付くため、変更前の表示がキャッシュに残るのを防ぎます。

出力だけ作る場合：

```powershell
npm.cmd run site:build -- --preview
```

毎回、新しい `dist-web-test/site-official-…` フォルダーを作ります。以前の出力やアプリ用の書き出しを上書きしません。既存の配信スクリプトで、出力先を指定して表示することもできます。

```powershell
node scripts/serve-web-test.cjs dist-web-test/site-official-出力された文字列 8105
```

`--yahoo` は不要です。紹介サイトから商品検索APIへ接続しません。

## 公開先・ストアURLの設定

`website/site-config.json` の3項目で設定します。空欄は `null` のままにします。

| 項目 | 設定するもの |
| --- | --- |
| `siteUrl` | 公式サイトを置くHTTPSの基点URL。GitHub Pagesのプロジェクト用パスも含め、末尾を `/` にする。プレビューでは未設定でよい |
| `appStoreUrl` | 実際に配信が始まったApp Storeのアプリページ。設定するとiPhoneの配信中表示とリンクが有効になる |
| `googlePlayUrl` | 将来必要になった場合のGoogle Playアプリページ。現在のiPhoneのみの計画では `null` のまま |

URLはHTTPS・認証情報なしに限定し、ストアは公式ホストとアプリページ形式を検証します。形式の検証は、そのアプリが本当に公開済みであるという確認の代わりにはなりません。配信ページを開いて確認した後に設定してください。料金や対応OSが決まったらFAQも実際の内容に合わせて更新します。

## 表示速度とアクセシビリティ

- フレームワークの追加配信や外部フォント取得がない静的ページ。初期表示の実画面は優先読み込み、それ以外は遅延読み込みです。
- 画像に幅と高さを設定し、読み込み時の配置のずれを抑えます。
- スクロールで一度だけ自然に表示。スマホ画像は小さく上下し、ボタンには控えめな反応を付けています。
- 「動きを減らす」設定ではアニメーション・滑らかなスクロールを止めます。JavaScriptや表示監視の機能が使えない環境でも本文は表示します。
- 本文へのスキップ、見出しの階層、画像の説明、フォーカス表示、44px以上の主要操作ボタン、メニューのEscape操作、ギャラリーのキーボード操作に対応しています。
- 基本の日本語SEOとOG情報を用意し、正式出力では設定したURLからcanonical・OG画像・サイトマップを作ります。プレビュー3ページはnoindex、robots.txtは巡回しない設定です。

2026-10-26にポリシーページの読みやすさを調整しました。本文・表を16pxにし、見出しの余白と区切りを増やしています。PCでは追従する11項目の目次、スマートフォンでは標準の開閉式目次から各見出しへ移動できます。表は狭い画面で項目名・説明を縦に並べ、横幅に収めます。行・列の見出しとtableの意味付けを保持し、本文を折りたたんで隠す構成にはしていません。

`docs/privacy-policy.md` の文言は変更せず、見出し・本文・表が元の原稿と同じ順序・内容で出力されることを `tests/policy-site.test.cjs` で確認します。目次の移動先・重複する見出し・HTMLのエスケープも回帰テストの対象です。ブラウザーでPC・390px・320px・768px幅を確認し、446件のテストと型チェックが成功しました。実機iPhoneのSafari・VoiceOverでの確認は別に必要です。

## アプリの正式ポリシーを掲載する前に

1. [ポリシーの確認事項](privacy-policy-publication.md)と[問い合わせ運用](support-operations.md)を確定する。保存期間・施行日・配信先のログ・検索APIの運用先などを未確定のままにしない。

4. 出力フォルダーの内容だけを静的ホスティングに配置する。プレビューは15ファイル、正式出力はサイトマップを含む16ファイル。`.env`、`publication.local.json`、在庫DB、問い合わせ回答、リポジトリ全体を混ぜない。
5. HTTPSでページと素材が開くことを確認し、アプリ・App Store Connect・フォームのポリシーURLへ反映する。

アプリ開発元の手動Webテスト公開ワークフローは、Webアプリのテスト配布用です。紹介サイトは上記の別リポジトリから公開し、両者の配信元を混ぜません。
