# Expo SDK 58への更新（2026年10月26日）

## 何を・なぜ変えたか

iPhoneのExpo GoがSDK 58用へ更新され、SDK 57のプロジェクトを開けなくなったため、利用者の了承を得てSDK 58へ移行しました。アプリ名・slug・EASプロジェクトID・Bundle IDは保持します。画面の構成・配色、AsyncStorageの保存キー・世代方式・削除保護、バックアップv1/v2の形式は変更していません。

| 対象 | 更新前 | 更新後 |
| --- | --- | --- |
| Expo | 57.0.30 | 58.0.19 |
| React Native | 0.86.3 | 0.88.0 |
| React / React DOM / react-test-renderer | 19.2.3 | 19.3.0 |
| Gesture Handler | 2.32.0 | 3.3.0 |
| Reanimated / Worklets | 直接依存なし | 4.7.1 / 0.13.0 |

`npx.cmd expo install 'expo@^58.0.0' --npm` と `npx.cmd expo install --fix --npm` で公式の対応版へ揃えました。後継のスワイプ部品が使うReanimated・Worklets、Reactと同じ版のreact-test-rendererも `expo install` で導入しています。CIテストが以前から直接使用していたyaml・semverを開発依存へ明示し、Expoの間接依存から外れてもテストが動くようにしました。Nodeは引き続き24.19以降の24系です。

## APIの互換性への対応

- `backupImages.ts` と `backupFileAccess.ts`：SDK 58で非同期になった `File.write()` を、同期版の `writeSync()` へ置換。写真の書き込み完了→容量確認→世代の切り替え、およびJSONの書き込み完了→共有の順序を保ち、書き込み失敗時は共有・復元を中止します。
- `SwipeableFoodCard.tsx`：Gesture Handler 3で削除された旧Swipeableを `ReanimatedSwipeable` へ移行。コールバックが「表示された側」から「指を動かした方向」へ変わったことに対応し、右スワイプで廃棄確認・左スワイプで使い切り確認を維持します。閉じてから確認処理を呼ぶ順序、しきい値・表示文言・色は保持します。
- 入力欄・日付パネル・一覧の参照を、React NativeのStrict TypeScript APIの `TextInputInstance` / `ViewInstance` / `ScrollViewInstance` へ変更。古い型への切り戻しや型検査の無効化は行っていません。
- 画像のreadonly配列型、解決できない内蔵画像、Alertのnullable引数を新しい型定義に合わせて扱います。画像のエラー表示・再試行と既存の確認ボタンを保ちます。
- `AGENTS.md`・README・開発ガイド・iPhone公開手順の現行SDKの参照先を58へ変更。過去の監査・Phaseの確認記録はSDK 57当時の記録として残します。
- npmのOSS通知と収集範囲の記録を再生成しました。

## 確認した方法

- 更新前：`npm.cmd test` 436件成功。
- 更新後：`npm.cmd test` **443件成功**、`npm.cmd run typecheck` 成功。
- `tests/sdk58-compatibility.test.cjs` に、JSONを書き終えてから共有すること、書き込み失敗時の中止、埋め込み写真の同期復元、スワイプの方向と確認順序、画像配列の失敗・再試行、nullableな確認ダイアログ、未解決の画像の読み込みを追加。
- `tests/data-protection.test.cjs` のファイルモックを同期版へ合わせ、既存の保存・復元失敗・削除保護のテストも実行。
- `npx.cmd expo install --check`：オンラインの公式推奨版と一致。
- `npx.cmd expo-doctor`：**20/20項目成功**。
- `npx.cmd expo export --platform all`：iOS・Android・WebのJavaScript／画像の書き出し成功。署名付きネイティブビルドの確認ではありません。
- 外部接続のマニフェストが `sdkVersion: 58.0.0` を返し、iPhone用の開発コードがHTTP 200で取得できることを確認。
- Yahoo常設APIでJAN `4901625421798` の商品名を取得。配信コードに常設URL・正式ポリシーURLが含まれ、設定済みのYahoo Client IDがマニフェスト・コードへ含まれないことを確認。
- ローカルWeb版のホーム・食材登録画面・日付パネルをブラウザーで確認。iPhone上の起動・カメラ・通知の確認とは区別します。

## 安全性・配布前の残件

同日のnpm auditは更新前11件（高6・中5）から更新後6件（高6）へ減りました。node-forgeとzod、およびそれらを参照するExpo CLI・設定関連の間接依存に指摘が残っています。SDKを古い版へ戻す `npm audit fix --force` や、指摘を除外する設定は使用していません。修正版の提供状況と利用箇所の評価が必要です。件数は影響するパッケージ数で、独立した攻撃経路の数ではありません。

OSS通知は525パッケージを収集し、パッケージ直下にライセンス本文がない48件を `oss-notice-coverage.json` に記録しました。過去の531パッケージ・57件から依存の構成が変わっています。新しく検出されたReact Nativeのビルド用パッケージとFlowのパッケージも含め、最終配布物のライセンス確認は引き続き必要です。

## 実機で確認が必要な項目

1. Expo Goのエラー画面からホームへ戻り、新しいSDK 58のQRで起動する。既存在庫・写真・レシピが残っていることを確認する。元データの保護のためExpo Goを削除しない。
2. 食材の登録・編集、日付選択、文字入力とフォーカス、右スワイプで廃棄確認・左スワイプで使い切り確認、そのキャンセルと取り消し。
3. 写真の撮影・選択、バーコードの繰り返し読み取り、Yahoo商品名検索、権限拒否・通信失敗からの再試行。
4. 写真付きバックアップの書き出しと復元。最初に現行データを退避し、ファイルが保存先にあることを確認する。
5. 通知許可・テスト通知・前面に戻った際の再同期・通知からの詳細表示。配布版の通知やiOS 27の画面遷移は、署名付きアプリでも別途確認する。
