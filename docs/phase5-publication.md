## 共有DBの審査・通報

- 商品の登録画面に禁止内容・利用目的を示す投稿ルールを表示。同意付きの任意チェックは初期OFF。ルールの版をヘッダーで送り、現在の版でない投稿はAPIが拒否する。
- 投稿は審査待ちで保存し、承認済みかつ非表示でない商品だけを検索で返す。審査待ち・却下・非表示はすべて404。登録完了画面は、投稿が公開済みか審査待ちかを区別する。
- 旧DBは元の内容・作成日時・非表示設定を保持し、すべて審査待ちに移行。過去の同意を推測で記録しない。更新前の停止・バックアップと、API／アプリを揃える手順を記載した。
- 共有の検索結果に、通報理由の選択と、共有情報を使わない手入力への切り替えを追加。通報の本文は理由だけ、対象はURLのバーコード。自由記述・在庫・写真・利用者IDは送らない。
- 通報は商品と理由ごとに集計。管理者CLIで審査待ち一覧、承認・却下、通報一覧、非表示・復元、対応済み記録を操作できる。通報数による自動非表示や公開の管理APIはない。

接続元の一時的な制限は維持し、DBに投稿者・通報者IDやIPを追加していません。個別の悪用者ブロック、実際の管理担当・対応期限、連絡先、サーバーと通報の保持期間は未確定です。ストアのUGC規定への対応がこれだけで完了したとは扱いません。詳細は [共有DBの運用手順](../server/README.md) を参照してください。

## 端末内データの一括削除

- 設定と読み込み失敗時の復旧画面に「この端末の保存データを削除」を追加。対象を確認し、「削除」と入力した場合だけ開始する。
- 現在の食材・履歴・買い物・自作レシピ・お気に入り・設定・商品候補に加え、復元前の原本、旧世代、壊れた記録、途中の保存先も削除する。
- ネイティブ版はアプリの保存領域にある管理用の写真ファイル、原本から参照される写真、一時バックアップ・原本JSONを削除する。期限通知・テスト通知の予約、通知センターの該当表示も削除する。
- 削除開始の記録を先に保存する。失敗や途中終了では、通常の読み込み・保存・復元を止め、削除の再試行を表示する。完了後はデモ設定にかかわらず在庫・買い物が空、通知OFF、内蔵レシピが初期状態になる。
- 削除前にキューへ入った書き込み、古い編集操作、準備済みのバックアップを書き出す操作を無効にし、削除した内容の再保存を防ぐ。別タブで保存先が変わった場合も古い保存を拒否するが、プロセス間の完全な排他制御ではない。

写真ライブラリの元画像、外部へ保存したバックアップ、共有商品DB、OS・SDK管理のキャッシュ、端末の権限設定は対象外。Web版は現在のブラウザーの同じサイトが対象で、他のタブを閉じてから操作する。OSのバックアップや記録媒体の上書き消去を扱う機能ではない。復元前の原本は通常2世代分を保持し、古い世代を復元成功後・正常な読み込み後に整理する。日時不明の世代は残す。仕組みと制限は [データ保護](data-protection.md) に記載した。

## 設定

`.env.example` の以下の値を `.env` または配布ビルドの環境に設定し、Expoを再起動／再ビルドします。すべて利用者に公開される情報です。

```dotenv
EXPO_PUBLIC_OPERATOR_NAME=
EXPO_PUBLIC_SUPPORT_EMAIL=
EXPO_PUBLIC_PRIVACY_POLICY_URL=
EXPO_PUBLIC_DEMO_DATA=false
```

ポリシーURLはHTTPSのみ。未設定や無効な値を入れた状態で公開しないでください。表示される説明は現在の実装に基づき、サーバーのログや運営方針はポリシーで補います。

## OSS通知の更新

依存関係を更新したら `npm.cmd run licenses`（または `node scripts/generate-oss-notices.cjs`）を実行します。npm形式・pnpm形式のインストールに対応し、実際のインストール先から取得します。

収集範囲はpackage.jsonのdependenciesと、そこから解決される依存・導入済みのpeer／optional依存です。ビルドツールも含む保守的な一覧で、すべてがアプリ実行時に同梱されるとは限りません。534件という数はこのPCの現在のインストール状態に基づき、package-lock.jsonのエントリー数とは異なります。

通知文が見つからない場合は、ライセンス名から著作権者や本文を推測して埋めません。配布対象との対応付けと、原作者の一次資料からの取得を追加で行います。最終ビルド環境で再収集し、本文の欠落・バージョン・ネイティブ／フォント通知を確認する必要があります。

## 検証

型チェック合格、自動テスト194件合格。出典・バックアップ・検索制限・初回起動・共有DBの審査と通報に加え、一括削除、通知・写真・保存先の各失敗、途中のキー削除、再起動相当の読み込みと再試行、古い書き込み・編集・バックアップ操作の無効化、WebでネイティブAPIを呼ばないことを確認しました。iOS／Android／WebのExpo export合格（JS・アセットの書き出しで、署名済みネイティブビルドではありません）。

生成設定はiOSの `NSMicrophoneUsageDescription` がなく、Androidの `RECORD_AUDIO` は `tools:node="remove"` となることを前回確認済み。今回はWeb書き出しを別のローカルoriginで開き、在庫0件・買い物0件・通知OFFからの起動と、OSS本文の検索・表示を確認しました。既存の利用者データを消去して検証していません。

審査・通報の追加では、別のローカルoriginと `.review/` 内の一時DBで、承認済み商品の検索、理由選択、通報受付の表示、共有の商品名・分類を引き継がない手入力への移動をブラウザーで確認しました。運用DBへの投稿や公開サーバーへの通報は行っていません。

一括削除の追加では、別のローカルoriginで設定から対象の説明を開き、確認入力が空の間は実行ボタンが無効になること、キャンセルすると説明を閉じることをブラウザーで確認しました。実際の登録データは削除していません。削除処理と失敗からの再試行は、テスト用の保存領域・写真・通知で検証しています。確認画面は `.review/phase5-erasure-confirmation.png` に保存しました。

生成設定で権限が削除されても、すでにインストールしたアプリの権限は変わりません。Expo Goの権限とも別です。新しい配布ビルドのManifest／Info.plistを最終確認します。

権限設定の根拠：[Expo ImagePicker SDK 57](https://docs.expo.dev/versions/v57.0.0/sdk/imagepicker/)・[Camera SDK 57](https://docs.expo.dev/versions/v57.0.0/sdk/camera/)。公開前監査は当初状態の記録として残しています。

OFFの出典・画像メタデータ・検索制限の根拠：[API案内](https://openfoodfacts.github.io/openfoodfacts-server/api/)・[画像のメタデータ](https://openfoodfacts.github.io/openfoodfacts-server/api/how-to-download-images/)・[ライセンス案内](https://openfoodfacts.github.io/openfoodfacts-server/api/tutorials/license-be-on-the-legal-side/)。この作業のテストでは外部APIをモックし、公開APIへの架空商品投稿はしていません。
