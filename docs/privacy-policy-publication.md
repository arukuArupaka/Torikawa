## 掲載する手順

1. 本文の `【公開前に設定：…】` を実際の値に置き換え、配布構成に合わない段落を調整します。この原稿の「掲載用原稿・未施行」の注記を外すのは、それらが確定してからです。
2. 本文をログイン不要のHTTPSページへ掲載します。スマートフォンでも読みやすく、運営者情報・連絡先・改定日を確認できるようにします。掲載先は紹介サイトと同じGitHub Pagesです。現在の公開ページはWebサイト向け説明なので、正式本文への差し替えが必要です。下記のコマンドで、ポリシー・サポートだけのHTMLを用意できます。
3. `publication.local.json` の `operator`・`supportFormUrl`・`privacyPolicyUrl` を設定し、`npm.cmd run publication:check -- publication.local.json` で形式を確認します。旧 `supportEmail` はフォームURLへ置き換えます。本文の適合や到達性を自動判定するチェックではありません。
4. Webテスト版では `--publication-config publication.local.json` を指定して書き出します。ネイティブ版は `EXPO_PUBLIC_SUPPORT_FORM_URL` などの公開値を開発手順に従って反映・再ビルドします。設定画面と案内ページから正式ポリシーとフォームが開き、送信内容を担当者が確認・回答できることを実際の配布版で確認します。

`data-handling.html` は機能の説明ページで、正式なポリシー本文の代わりではありません。HTMLの作成はローカルだけで、GitHubへのpush、Pagesの公開、アプリの配布設定へのURL反映は自動では行いません。

## 掲載ページの作成

```powershell
# 未確定項目を明示した、手元での確認専用の出力
npm.cmd run policy:build -- --preview

# 未確定項目と未施行の注記を解消してから使う、正式掲載用の出力
npm.cmd run policy:build
```

成功時に `dist/policy-…` の新しいフォルダーを表示します。`index.html`・`privacy.html`・`support.html` の3ファイルだけを出力します。運用手順、ローカル設定、在庫、フォームの回答は読み込まず、コピーもしません。既存の出力は上書きしません。依存の追加、外部画像・解析スクリプト・外部フォントの読み込みはありません。

`--preview` は全ページへ確認用の注意とnoindexを付けます。正式出力では本文に `【公開前に設定：…】`・`【運営確認待ち：…】`・「掲載用原稿・未施行」が残っていれば、出力前に停止します。これは原稿の置き忘れ防止であり、法令適合・実際の設定・リンク到達性を保証するものではありません。未確定表示を消すだけでチェックを通さず、担当者が実際の構成と運用を確認します。

公開するのは、この3ファイルだけです。掲載先のホスティングが決まってから第9項のログ・配信事業者の説明を確定し、HTTPSで開けるURLをアプリとApp Store Connectに設定します。
