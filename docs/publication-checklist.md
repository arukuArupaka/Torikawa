## 1. 公開する連絡先とポリシー

- [x] 問い合わせフォームのHTTPS URLを設定する（2026-10-22、[回答者用フォーム](https://forms.gle/Rjoy4xiwzE7uBDf57) の画面を確認）。
- [ ] 運営者の表示名を決める。仮の連絡先は掲載しない。
- [ ] フォームを利用者として開いて送信し、担当者側で閲覧・回答できることを確認する。回答者に他の回答や管理画面を公開しない。
- [x] 利用者向けの[掲載用本文](privacy-policy.md)と、運営者向けの[掲載前の確認事項](privacy-policy-publication.md)を分けて準備する（2026-10-20、未施行）。
- [ ] 掲載用本文の未設定箇所を埋め、実際のホスト・通信・ログ・保持・問い合わせ対応に合わせる。
- [ ] 正式なポリシーをHTTPSで掲載し、ログインせず読めることを確認する。
- [ ] 公開設定を指定して書き出し、アプリと案内ページで連絡先・ポリシーリンクを確認する。

連絡先が揃ったら、既存ファイルを上書きしないよう、未作成の場合だけ次を実行します。

```powershell
Copy-Item publication.example.json publication.local.json
```

`publication.local.json` の `operator`（運営者）、`supportFormUrl`（問い合わせフォームのHTTPS URL）、`privacyPolicyUrl`（正式ポリシーのHTTPS URL）の3項目を入力します。このファイルはGit対象外ですが、指定した値は配布物に含まれる公開情報です。旧設定の `supportEmail` は `supportFormUrl` に置き換えます。`data-handling.html` はアプリの動作説明であり、正式ポリシーの代わりではありません。

2026-10-22現在、ローカルの `publication.local.json` はフォームURLだけを設定してあります。残り2項目が空なので、次のチェック・公開用書き出しはまだ成功しません。Expo Go向けには `.env.local` の `EXPO_PUBLIC_SUPPORT_FORM_URL` に同じURLを設定済みです。

```powershell
npm.cmd run publication:check -- publication.local.json
npm.cmd run web:test:export -- --publication-config publication.local.json --yahoo
```

チェックは必須3項目と形式だけを確認し、メールアドレスは要求しません。フォームの送信・回答やURLの到達性、本文・権利・法令への適合を自動判定しません。欠落や不正な形式、3項目以外の混入は失敗とし、ファイル内容をエラーに出しません。

設定未指定の書き出しはこれまで通り連絡先を「準備中」とし、ローカル `.env` を読みません。API認証情報はこのJSONへ入れません。Yahoo検索は別途サーバーに設定したIDで動きます。`--yahoo` を外すと検索OFFです。GitHub Pagesへ静的配置するだけではYahooのサーバーは動きません。

## 2. 配布物と公開環境

- [ ] 固定のHTTPS URLと、必要な検索サーバーの運用先を決める。
- [ ] URL変更前に必要なデータをバックアップし、移行先で復元する。
- [ ] 本番ホストのログ項目・目的・閲覧者・保持期間・削除方法を把握し、ポリシーに反映する。
- [ ] 配布物にClient ID、秘密鍵、個人の在庫・写真・バックアップが含まれないことを確認する。
- [ ] 初回は在庫・買い物が空、デモOFFであることを確認する。
- [ ] `test-guide.html` と `data-handling.html` を開き、YahooのON/OFFと説明が一致することを確認する。
- [ ] 更新前にバックアップし、更新後も既存の登録・写真が残ることを確認する。

共有DB接続はこのWeb書き出しではOFFのままです。公開を始める場合は管理担当・審査・通報対応・訂正／削除依頼・保持期間を先に決めます。個人の在庫を共有する機能にはしません。

## 3. 素材・サービスの確認

固定素材の出所・ファイルごとの状態は [素材の確認記録](asset-sources.md) を参照してください。Expo標準アイコン6点の元ファイル一致とMIT本文を確認済みです。2026-10-20に旧レシピ写真8枚を生成画像へ置換し、全136枚の制作記録を揃えました。最初の8件と端末内候補13種の手順も作成し直し、新規の写真未設定表示・デモ画像の固定Unsplash参照はアイコンへ変更しました。利用者の過去の外部画像、API・商標・最終配布物全体の確認は別です。

- [x] 内蔵136枚の画像を制作記録のあるものにし、新規の出所不明の初期画像を使わない。
- [x] 最初の8件・候補13種の手順を作成し直し、未編集レシピだけを安全に更新する。

- [ ] アイコン・レシピ画像・文章ごとに出所と利用条件を記録する。不明な素材は確認できるものへ差し替える。
- [ ] Yahooの商品名の保存・再利用条件を確認する。画像を使わない対応だけで確認済みとしない。
- [ ] Yahooのクレジットが公式の位置・リンク・表示になっていることを公開先で確認する。
- [ ] Open Food Factsのデータと画像の出典・ライセンス、連絡先・識別方法・利用制限を確認する。旧データも対象とする。
- [ ] 最終配布物のOSS・フォント等の通知を確認する。収集スクリプトの未確認項目をそのまま許諾済みと扱わない。
- [ ] アプリ名の商標、広告・課金の有無、公開対象を決め、該当する条件を確認する。

## 4. iPhone Safariでの操作確認

以下はテスト用データで行います。データ削除を試す前にバックアップし、保存したファイルを確認してください。

| 操作 | 合格条件 | 結果 |
| --- | --- | --- |
| 商品検索・手入力から登録 | 保存ボタンを見つけて完了できる。商品名・実際の数量・包装の期限を確認できる | 未確認 |
| カメラ・写真の許可と拒否 | 許可で利用でき、拒否しても手入力などで続けられる | 未確認 |
| 写真登録後にSafariを閉じて再訪 | 登録と写真が表示される | 未確認 |
| 使い切り・廃棄・取り消し | 在庫と履歴が意図通り変わる | 未確認 |
| 写真付きバックアップを新しいテスト用保存先へ復元 | 数量・期限・写真が戻る | 未確認 |
| 保存データの一括削除 | 消してよいテストデータだけが対象となり、再訪で復活しない | 未確認 |
| 通信OFF・商品未発見 | 分かる案内が出て、手入力で登録できる | 未確認 |
| 文字拡大・VoiceOver | 主な操作と説明を読める。保存や確認を操作できる | 未確認 |
