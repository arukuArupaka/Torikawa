# 登録・追加の操作フィードバック

2026-10-12に、既存の見た目に合わせてボタンの押下と保存完了通知を追加しました。

- 共通ボタンは押下中に見た目だけを94%へ縮め、離すと220msで元へ戻します。短いタップでも押下状態が見え、タップ領域の大きさは保ちます。
- ホームの食材追加と買い物リストの追加ボタンも、同じ押下の動きを使います。50pxのタップ領域と無効時の扱いを保ちます。
- 「写真・カテゴリ・購入日・メモ」と「よく買うもの」は約260msで開閉します。閉じてもフォームの入力値は保ち、閉じた内容は操作・読み上げの対象から外します。動きを減らす設定では即座に切り替えます。
- 同じ開閉を、食材登録の「前の登録から選ぶ」、レシピの「絞り込み」「もっと探す」「食材からレシピ候補を作る」「材料の確認」にも使います。検索語・選択条件・前回登録の検索内容は閉じても保持します。レシピ候補は最初に表示を求めたときに作り、閉じる動きの途中で内容が消えないように保ちます。
- 食材詳細の「調理での使用履歴」は件数付きの見出しにまとめ、必要なときに開くと新しい順の記録を表示します。現在の期限・残量、使い切り・廃棄・編集の操作は常に表示し、履歴の開閉では記録を変更しません。
- ホームの「期限順・保存場所別・カテゴリ別」は選択状態と食材の区分を即座に更新し、1つの選択背景を280msで横移動させます。食材カード・区分見出しは10px下から、55%の不透明度で280msかけて現れます。検索や在庫の更新では動きを再開しません。動きを減らす設定では即座に表示し、途中で設定を変えた場合も通常の表示へ戻します。画面幅が変わると選択背景は新しい位置へ即座に合わせます。
- 食材の新規登録・編集、買い物リストの手入力・よく買うものからの追加は、端末への保存が成功してから完了通知を表示します。
- 失敗時は成功通知を出さず、既存の保存エラーと再試行案内を残します。再試行で保存できたら一度だけ通知します。重複追加、削除済みの項目、復元・データ入れ替え前の操作は古い完了通知を出しません。
- 通知は下部タブとキーボードを避けて表示し、閉じるボタンを備えます。通常4秒表示し、Webではステータスとして読み上げに伝えます。
- ホームのスワイプと食材詳細の「使い切った・捨てた」は、端末への保存後に「元に戻す」付きの通知を8秒表示します。ボタンにフォーカスがある間は自動で閉じません。通知が消えた後も、統計の記録や食材詳細から取り消せます。
- 「元に戻す」は対象の食材だけを管理中に戻し、残量・消費履歴を保ちます。買い物リストへの追加を選んだ場合は、その追加を取り消さないことを通知に表示します。対象の食材を後から編集・削除・取り消した場合、バックアップ復元やデータ入れ替えを行った場合、古い通知の操作は適用しません。連打も一度だけ受け付けます。
- 記録・取り消しとも保存に失敗した場合は成功通知を出しません。既存の保存案内から再試行し、保存できたときに一度だけ通知します。
- 初回の操作ガイドや確認ダイアログが開いている間は完了通知を保留し、閉じた後に表示時間を数え始めます。
- iOS・Androidの画面読み上げが有効なときは自動で消しません。Androidの操作時間設定にも合わせます。iOSの読み上げは他の発話の後へ予約します。
- 端末の動きを減らす設定が有効なときは、ボタンの縮小と通知の移動を省きます。設定が未取得の場合も動かさず、変更した設定を途中から反映します。

確認・選択・失敗のダイアログは完了通知へ置き換えていません。商品候補の学習や共有APIの結果は、食材の端末保存とは別の結果です。

参考にした動き：[ボタンを押す](https://motion-reference.takayustudio.jp/#motion=ui-press)、[トースト通知](https://motion-reference.takayustudio.jp/#motion=ui-toast)。デモのコードや素材は取り込まず、React NativeのAPIで実装しました。

自動テストでは保存待ち・失敗・再試行・重複・データ入れ替え、通知の入れ替え、読み上げ・動きを減らす設定の変更、Androidの操作時間設定を確認します。OSのAPIはモックによる検証です。

折りたたみは、途中で開閉を切り替える操作、開いている途中の内容の高さ変更、動きを減らす設定への切り替え、メモの保持も確認します。ネイティブでは高さを測って短く動かし、開いた後は通常のレイアウトへ戻します。WebではCSSのグリッドで高さに追従し、閉じた内容は `inert` にしてキーボードフォーカスも防ぎます。

一覧の表示方式は、更新をアニメーションの完了待ちにせず、連続タップでも最新の選択を使います。フェード値は表示中のカードで共用し、SectionListの仮想化を維持します。アニメーションを理由にリストのキー変更やスクロール位置のリセットは行いません。

実機では、食材登録と買い物追加の後の表示、キーボードとの位置関係、VoiceOver／TalkBackの読み上げ、動きを減らす設定を確認してください。自動テストとWebの確認だけで実機の合格とは判定しません。
