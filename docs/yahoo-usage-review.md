## 公式PDFマニュアルによる補足

[公式ヘルプ](https://support.yahoo-net.jp/PccDeveloper/s/)が案内する[ユーザーズマニュアル](https://s.yimg.jp/dl/developer_network/image/download/shopping/yjdnshpapi.pdf)も確認しました。取得できた版はVer.1.13、2024-10-15、75ページです。全ページをテキスト抽出し、関係する8・14・74ページは画像でも確認しました。

- 8・14ページでは、商品検索を含む「ショッピング情報取得API」と、認証連携を伴う「ストア運営をサポートするAPI」を分け、登録の導線も区別しています。この区分は、登録画面と本アプリの呼び出し先を照合する参考になります。
- これは技術・登録手順の区分で、出店APIの保持制限が本アプリに必ず適用される、または必ず適用されないという法的な結論までは導きません。商品検索（v3）の現行ページが案内する約款との関係は、引き続き未確定です。
- このPDFには本アプリの端末保存・再登録候補・バックアップを明示的に許可する説明は見つかりませんでした。資料の作成時点と現行の個別条件が同じだと仮定しません。
- 74ページと現行ヘルプの両方に、ショッピングWeb APIの問い合わせフォーム終了の案内があります。原稿を作っただけで、個別確認を受け付ける窓口が確保できたとはしません。

さらに[公式アフィリエイト案内](https://developer.yahoo.co.jp/webapi/shopping/affiliate.html)には、別途の登録・提携による利用方法があります。これを本アプリの商品名保存や、未定の広告・課金への包括的な許可と読み替えません。

## 実際のデータの流れ

| 処理 | 読んで確認した実装 | 現在の動作 |
| --- | --- | --- |
| Yahooへの問い合わせ | `server/yahoo-product-lookup.cjs` | JANで検索し、応答から商品名・JAN・出典URLだけを返す。画像・説明文はアプリへ返さない |
| 検索サーバーの保持 | `deployment/yahoo-lookup/handler.cjs` | 永続化は回数制限用の数値のみ。商品カタログや検索結果の永続キャッシュは作らない。上流のJSONは要求処理中に解析する |
| 入力の補助・加工 | `src/services/yahooProductLookupService.ts` | 商品名から食材名・分類・タグ・保存場所の初期値を推定し、出典と取得日を付ける |
| 食材として保存 | `src/screens/AddFoodScreen.tsx`、`src/context/AppDataContext.tsx` | 利用者が確認して保存すると、商品名と出典も食材データとして端末に残る |
| 次回への再利用 | `src/services/learnedProductService.ts`、`src/services/productLookupService.ts` | バーコード商品の保存時に商品候補を端末へ記録し、次の同じバーコードでは外部検索より先に利用する。一定期間後の再取得・自動失効はない |
| バックアップ | `src/services/backupService.ts` | 食材と端末の商品候補、その出典をファイルへ書き出し、利用者が選んだ保存先・共有先へ渡す。他端末での復元にも使う |
| 共有商品DB | `src/screens/BarcodeScreen.tsx`、`src/screens/AddFoodScreen.tsx` | 通常の登録導線では、全検索で未取得だった場合にのみ共有を提示する。Yahooで取得した結果・端末で再利用した商品候補には提示しない。汎用APIだけで商品名の出所を判定できるという保証ではない |

サーバーで結果を保存しないことと、端末にも保存しないことは異なります。また、利用者による名前の確認・編集が、元データの利用条件を自動的に解除する根拠とは判断していません。既存のバックアップ互換性やデータ保護を崩して対処しません。
