# Phase 4：入力負担と表示速度

[READMEへ戻る](../README.md) · [使い方](USAGE.md)

2026-09-30時点で実装、自動テスト、Webでの画面・500件データの確認を実施しました。実機での速度・大きい文字・読み上げと、初見利用者による操作確認は未実施です。Phase 4の受け入れ条件をすべて満たしたという判定ではありません。

## 変更した操作

- ホームの最上部に期限切れの件数と確認ボタンを追加。検索に隠れていても在庫全体の件数が分かり、押すと期限切れだけを表示します。期限内の食材を使うレシピへの案内とは分けています。
- 登録画面は表示名・期限・残量を優先。単位・保存場所・レシピ用分類は確認できる状態を保ち、写真・カテゴリ・購入日・メモを折りたたみました。値は閉じても保持します。
- 買い物一覧の上部に「買うもの／購入済み」の切り替えを置き、大量の項目があっても購入済みへ進めます。
- 登録食材に購入元のIDを保存し、購入済み項目に「登録済み · 食材を確認」を表示。確定時にも最新の購入状態と登録状態を検査します。食材の1コレクション内で関連付けを保存するため、食材と買い物を別々に保存する途中で登録印だけが残る構造にはしていません。
- 買い物の重複判定はレシピと同じ表記揺れを利用。ブランドや加工品を推測で統合しません。関連付けがある購入分は「よく買うもの」で二重に数えません。
- 主ボタン・警告・期限切れ・補助文字の色を濃くし、検証対象の背景との通常文字コントラストを4.5:1以上にしました。選択項目にチェック表示を追加し、ネイティブ用状態とWeb用ARIA状態を指定しています。
- カレンダーの小さな商品名は件数表示へ変更。商品名は日付を選んだ下の一覧で確認します。タブラベルとフォームの補足文字も拡大しました。

購入元の関連付けは編集・使用・廃棄・バックアップ復元でも保持します。過去の記録に対する推測の関連付けは行いません。買い物項目を削除しても食材は残ります。食材を完全削除すると、その購入分は再登録できます。

## 計算と保存

- 同じ食材配列では分類別・期限順の索引を共有し、レシピごとに全食材の正規化と並び替えを繰り返さないようにしました。入力配列は変更せず、日付をまたいだら使用可能な在庫を更新します。
- 同じ在庫を複数の材料行で使う場合の検出も集計を共有し、二重割り当てを防ぐ従来の「要確認」を維持しています。
- 畳まれている端末内レシピ候補は、表示時に計算します。
- 保存成功済みのコレクションを記憶し、変更のない食材・レシピ・買い物・通知設定を再保存しません。失敗したコレクションは再試行対象として残し、写真回収は保存成功後に行います。
- ホームとカレンダーは食材用Contextを購読し、買い物や通知同期の状態変更だけでは再描画しません。Context全体の分割は行っていません。
- 通知と関係のない残量・メモだけの変更では通知同期を起動しません。期限・状態・表示名・設定変更やアプリ復帰では引き続き同期します。
- ホームと買い物をSectionListへ変更し、画面付近の項目だけ描画します。レシピ・統計一覧の仮想化、通知待機要求の集約・予約枠の上限設計は今回の変更に含めていません。実機計測を踏まえて追加判断します。

## 計測結果

Windows / Node v24.19.0、10分類の模擬食材、内蔵レシピ8件。3回のウォームアップ後15回の中央値です。毎回新しい在庫配列を用い、索引の作成時間も含めました。現行の同じ計算ロジックで「全件走査」と「共有索引」を比較しており、過去版アプリ全体の速度比較ではありません。

| 食材数 | 8レシピ照合・在庫判定：全件走査 | 共有索引 | 候補生成：全件走査 | 共有索引 |
| ---: | ---: | ---: | ---: | ---: |
| 10 | 1.687ms | 0.379ms | 1.302ms | 0.167ms |
| 100 | 14.764ms | 0.787ms | 11.193ms | 0.455ms |
| 500 | 67.368ms | 2.541ms | 55.075ms | 1.611ms |

**純粋な計算時間です。スマートフォンの描画・FPS・ストレージ速度を示す数値ではありません。** 再実行は `node tests/phase4-benchmark.cjs`。測定データは [phase4-benchmark.json](../review/phase4-benchmark.json)。

## 確認済み

- 自動テスト164件成功。従来の保存・復元・通知テストに加え、表記揺れとブランド区別、購入分の二重登録・古いフォーム・バックアップでの関連維持、変更領域だけの保存と失敗時の再試行、購読の分離、日付変更、索引と全件走査の結果一致、コントラストを確認。
- TypeScriptの型チェック成功。
- Expo SDK 57でiOS・Android・Web向けJavaScript／アセットのexport成功。ネイティブビルドの確認ではありません。
- Webの390px幅で期限切れの絞り込み、登録項目の順序、任意項目の開閉、保存場所の`aria-checked`を確認。ページ幅のはみ出しはありませんでした。
- 通常の8081とは別のローカル検証用ポート8082で、食材500件・買い物500件を読み込み。確認時のホームの描画カードは18件、買い物行は30件で、全500件は描画していませんでした。描画件数は表示幅・位置に応じて変わります。
- 500件目の食材を検索で取得。検証用の買い物1件を購入済み→食材登録→登録済みの表示まで操作し、在庫が501件になることを確認。通常の8081側の在庫はこの操作で変更していません。
