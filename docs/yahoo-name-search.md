# Yahooの商品名検索と画像の扱い

Yahoo!ショッピングAPI v3のJAN検索を、サーバー経由で利用します。アプリへ返すのはバーコード・商品名・出典の商品URLだけです。Yahooの商品画像・説明文・カテゴリ・ブランドは返しません。分類と保存場所はアプリで推定し、画像は食材アイコンで表示します。登録画面で自分の写真を選ぶこともできます。

保存済みのYahoo由来の外部画像は、読込・再利用時にアイコンへ切り替えます。自分で選んだ端末写真・埋込写真は保持します。Yahoo由来の情報は共有商品DBへ投稿しません。Open Food Factsの検索・出典付き画像は別の機能として継続します。

## Cloudflareで共有しているWeb版で有効にする

1. Yahooのアプリケーション管理で取得したClient IDを、Git対象外のルート `.env` に `YAHOO_SHOPPING_APP_ID=...` として設定する。IDはチャットやREADMEに貼らない。旧EXPO_PUBLICの設定は使わない。
2. `node scripts/export-web-test.cjs --yahoo` で書き出す。IDは書き出し処理で読み込まず、配布ファイルにも入れない。
3. 新しい出力フォルダーを指定して `node scripts/serve-web-test.cjs dist-web-test/site-… 8103 --yahoo` を起動する。サーバーだけが `.env` を読む。
4. そのサーバーへCloudflareトンネルを接続する。既存のトンネルを維持してサーバーだけを入れ替えると、URLとブラウザーの在庫保存先を維持できる。

ID未設定時はAPIが503を返し、アプリはOFF検索・手入力へ進みます。通常のWeb書き出しには検索APIのURLを設定しません。実際のYahoo検索を有効にするにはIDの設定が必要です。GitHub PagesやNetlifyへの静的ファイル配置だけではこのサーバーは動きません。

## 通信と制限

検索APIは `GET /api/yahoo-product?barcode=JANコード` です。8桁または13桁のチェックディジットを検証し、検索先は固定のYahoo APIだけです。在庫・数量・期限・メモ・写真は送信しません。応答にIDや画像URLを含めず、上流の例外も返しません。商品情報の永続DBはサーバーに作りません。

同じサーバー全体で1秒に1件まで・同時処理1件に制限し、超過は429です。上流通信は6秒で打ち切ります。Webテスト版では同じサイトからの利用に限定し、別Originからのアクセスは拒否します。ネイティブ向けの別HTTPS APIとして使う場合は、運用先のOrigin・アクセス制限を別途設計してください。

## 出典と残る確認事項

検索を設定したアプリには「Webサービス by Yahoo! JAPAN」を下部に表示します。Web版では公式のテキストリンクと余白を使います。[公式のクレジット表示](https://developer.yahoo.co.jp/attribution/)、[ID管理](https://e.developer.yahoo.co.jp/)、[商品検索仕様](https://developer.yahoo.co.jp/webapi/shopping/v3/itemsearch.html)を参照してください。

この変更は画像とIDの扱いを改善するもので、商品名の保存・再利用や将来の広告・課金を含む全用途の適法性・規約適合性を保証するものではありません。登録前には商品名とパッケージの期限を本人が確認します。
