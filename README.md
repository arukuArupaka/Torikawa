# たべどき！！

冷蔵庫の食材と期限を管理し、「食べどき」を逃さず食材ロスを減らすためのスマホアプリです。React Native + Expo SDK 57 + TypeScriptで作っているため、1つのコードからiPhoneとAndroidの両方で動かせます。SDK 57は今回使用するiPhone版Expo Goに合わせています。

このリポジトリは、最初から機能を詰め込みすぎない「動く最小版」から育てている学習用アプリです。食材、買い物リスト、通知設定、レシピ、学習済みバーコード商品は、サーバーではなく端末内のAsyncStorageへ保存します。

任意で商品情報だけを共有するAPIも追加しています。バーコード・商品名・レシピ用分類・カテゴリを他の利用者の入力補助に使い、個人の冷蔵庫の中身は共有しません。公開先は後から設定できます。[共有商品DBの起動・公開設定・運用手順](server/README.md)を参照してください。

- 今月の使い切り・廃棄比率を表示する円グラフ
- 全期間の廃棄記録から集計する「よく捨てているもの」ランキング
- ホーム左上の統計アイコンから統計画面へ直接移動

- 廃棄ランキングから「次回は少なめに買う」メモ付きで買い物リストへ追加

- 過去の登録食材と購入済みリストから作る「よく買うもの」候補

- 調理後に食材ごとに「使い切る・1個減らす・変更なし」を選択
- レシピ調理の確定と連動した食材状態・数量・通知・統計の更新
- レシピ調理で使い切った食材を、まとめて買い物リストへ追加
- 料理画像、料理名、時間、複数材料・分量、複数手順を入力するレシピ追加
- 登録レシピの編集・削除と、手順の並べ替え
- レシピのお気に入り切り替え・絞り込み

- iPhone・Android標準の日付ピッカー
- 冷蔵・冷凍・常温の保存場所選択
- 食材数量の登録・表示・編集

- バーコード商品も期限日・購入日・保存場所・数量を確認して登録

## 2026-09-23の見直し

- 保存データを読めない場合は既存データを上書きせず、再読み込み画面を表示します。保存失敗時は案内と再試行ボタンを表示します。同じ保存先への書き込みは順番を保証します。
- 材料判定は分類名と明示した表記ゆれで照合します。検索タグによる別食材の誤一致を避けるため、分類が広すぎる食材は登録画面で修正してください。
- 使用量の自動入力は、単位を換算できる分量だけに限定します。`1/4玉`は`0.25個`、`0.5kg`は`500g`として扱います。`少々`や単位不明、登録残量より多い場合は手入力します。残量を超える入力は確定しません。
- 期限の自動入力には目安である旨を表示します。ブラウザー版でも日付を変更できます。
- ブラウザー確認用の依存を追加しました。通知・カメラ・画像付きバックアップの最終確認は実機で行ってください。確認ダイアログはWebでも表示され、キャンセル・Esc・Tab操作に対応しています。

検証は`npm.cmd test`と`npm.cmd run typecheck`で実行できます。画面レビューと未対応の課題は[レビュー資料](review/REVIEW.md)を参照してください。

## バーコード登録の使い方

1. バーコードタブを開く
2. 初回はカメラの使用を許可する
3. 商品のJAN・EANバーコードを緑色の枠内へ映す
4. 商品情報を確認して登録画面へ進む
5. 期限日・購入日・保存場所・数量を入力または修正して保存する

同じコードの連続読み取りは自動で停止します。「もう一度読み取る」でカメラを再開できます。商品情報は、学習済み端末内カタログ、固定サンプル、Yahoo!ショッピング商品検索API、Open Food Factsの順に探します。見つからない場合は読み取った番号をメモへ引き継いで手入力できます。「サンプル商品で動作を試す」ではカメラを使わず登録フローを確認できます。

バーコードからは期限日・購入日・保存場所・数量を取得しません。商品が見つかった場合も自動保存せず、必ず入力画面でユーザーが確認してから登録します。アップデート前に保存した食材の数量は自動的に1として扱います。

バーコード登録では、商品名とレシピ用分類を分けて保存します。たとえば商品名が`明治おいしい牛乳`でも、レシピ用分類は`牛乳`として保存できます。登録画面で分類を手動修正した場合は、そのバーコードに対する分類情報も端末へ保存し、次回同じバーコードを読み取ったときに優先して使います。

商品名からレシピ用分類を自動推測するルールには、牛乳、ヨーグルト、卵、豆腐、納豆、チーズ、パン、米に加えて、ベーコン、ソーセージ、ツナ、トマト缶、玉ねぎ、じゃがいも、パスタ、醤油、味噌、めんつゆなどを登録しています。

オンライン検索にはインターネット接続が必要です。Yahoo!ショッピングとOpen Food Factsのデータは、商品によって未登録または不完全な場合があります。取得元は読み取り結果に表示します。

## ホームから期限が近い食材を使う

ホーム上部に、在庫全体の「今日まで」「明日〜3日以内」の登録件数を表示します。期限切れ・使用済み・廃棄済みの食材は含めません。検索欄や表示順を変えても、この件数は在庫全体を示します。

「この食材でレシピを探す」で、期限が近い食材を使うレシピへ進めます。以前の料理名検索やカテゴリ条件は解除されます。期限が近い食材がない場合は「レシピを見る」からすべてのレシピを開けます。ホームとレシピの期限判定は日付の切り替わりとアプリ復帰時に更新します。

食材カードの保存場所・数量は14pxに拡大し、狭い画面では項目ごとに折り返します。商品名は2行まで表示します。

## レシピ機能の使い方

レシピ画面は料理の写真・名前・調理時間・使える食材から見始められます。「絞り込み」で条件やカテゴリを選び、選択中の条件は閉じたあとも表示します。「もっと探す」からクックパッド検索や食材を組み合わせた候補を開けます。各料理の「確認」を押すと材料の一致率と不足材料が開き、買い物リストへ追加できます。

詳細の材料一覧は、材料名と必要量を横並びにし、その下に登録残量と期限を表示します。該当する在庫がない材料は「在庫未登録」と表示します。期限切れの在庫がある場合は「使用対象外」と区別し、使用量の記録には含めません。「ゆで用」など分量に添えた括弧内の補足は別行で表示します。

レシピの追加・編集では「分量の基準（人分・任意）」に1〜99人分を設定できます。空欄は人数未設定です。材料・分量は入力した基準の人数に対応させてください。詳細の「作る人数」を増減すると、材料表と「使った分を自動選択」の提案を人数に合わせて計算します。閲覧時に人数を変えても、保存した基準人数・材料・分量は変更されません。

分数や「大さじ1と1/2」も換算します。「適量」「少々」などはそのまま表示し、「2〜3個」「1個（約200g）」など自動換算できない表記には「元の分量・要確認」と表示します。作り方の文章や加熱時間は変更しません。人数変更時は使用量の選択を解除するので、調理後に再度選択してください。単位が一致せず換算できない使用量や、在庫を超える提案は自動入力せず、実際の使用量を入力します。

初期レシピは材料量に合わせた目安として、オムレツ・卵サンドを1人分、ほかの6品を2人分に設定しています。既存データは内容が初期レシピと一致し、人数欄がまだ存在しない場合だけ補完します。編集済み・自作・保存済みの提案レシピには人数を推測しません。明示的に空欄にした人数や、設定済みの人数は再起動・バックアップ復元でも維持します。

詳細の「買い物の準備」から、選んだ人数に合わせた必要量をメモに付けて材料を追加できます。対象は使える在庫がない材料（未登録・期限切れ）です。在庫がある材料の不足量は計算しません。調理用の水と未購入リストにある同名の材料は追加せず、既存メモも上書きしません。換算できない分量は「元の分量」「要確認」と明記します。

レシピ詳細でも日付変更・アプリ復帰時に期限を再判定します。調理記録の確認中に食材が期限を過ぎた場合は、確定を止めて選び直しを案内します。

レシピ画面では、登録されている管理中の食材をもとに「材料の一致率」を計算します。これは材料の種類がそろう割合で、分量が足りることを保証しません。「材料あり」で絞り込んだ場合も、詳細で必要量と残量を確認してください。

初期レシピ8品と端末内で提案するレシピは、調味料や炒め油も材料・分量に含めています。調理用の「水」は材料一覧に表示しますが、一致率・不足食材・買い物への追加・使用量の記録には含めません。「ミネラルウォーター」など別の名前で指定した材料は通常どおり在庫と照合します。

旧版の初期レシピは、名前・分類・時間・材料・分量・手順が元の内容のままであれば、起動時とバックアップ復元時に不足材料を補います。お気に入り・写真・作成日時は保持し、編集済みのレシピや自分で追加・保存したレシピは変更しません。削除した初期レシピも復活させません。

判定は`ingredientName`（未設定の場合は表示名）の一致と、卵／たまご・醤油／しょうゆなど明示した表記ゆれで行います。検索用タグや部分一致は使わず、豚肉を牛肉、卵豆腐を卵として扱う誤判定を防ぎます。自動分類が広すぎる場合は食材登録画面で修正してください。

例:

- 商品名: `明治おいしい牛乳`
- レシピ用分類: `牛乳`
- タグ: `牛乳`, `乳製品`, `飲み物`

この場合、レシピの必要材料が`牛乳`なら「持っている」と判定されます。期限切れの食材はレシピ候補から除外し、期限が近い食材を使えるレシピを優先します。

レシピ詳細では、調理後に食材ごとに次の操作を選べます。

- 変更なし
- 使用量を入力して残量を減らす
- 全部使い切る

クックパッド連携は、期限が近い管理中の食材から検索キーワードを作り、クックパッドの検索ページを外部ブラウザで開きます。レシピ本文や画像をアプリ内に取り込むことはしません。

## 期限通知の使い方

1. 設定タブを開く
2. 数字を入力して「追加」を押し、通知日を必要な数だけ登録する
3. 通知時間を決める（`0日前`は期限当日）
4. 「通知設定を保存」を押して通知を許可する
5. 「3秒後にテスト通知」で端末に表示されることを確認する（食材登録済みなら、通知タップで詳細画面も確認できます）

追加した通知日はチップをタップすると削除できます。食材の追加・編集・削除後は、予約済みの期限通知も自動で更新されます。通知をOFFにして保存すると、このアプリが予約した期限通知を解除します。以前の単一通知設定は、その日数を1件含む複数通知設定へ自動移行します。

期限通知をタップすると該当食材の詳細画面が開きます。アプリが開いている場合、バックグラウンドの場合、終了している場合のいずれにも対応しています。食材が既に削除されている場合はホーム画面を表示します。設定画面の「通知の状態」では、通知権限と現在予約中の期限通知件数を確認できます。

## バックアップと復元

1. 設定タブの「データ管理」を開く
2. 「バックアップを書き出す」を押し、JSONファイルをファイルアプリやクラウドへ保存する
3. 復元する端末で「バックアップから復元」を押す
4. 保存したJSONを選び、作成日時と件数を確認して「復元する」を押す

端末内に保存した食材・レシピ・バーコード商品の画像は、JSON内へ含めて別端末で再生成します。そのため画像が多い場合はファイルサイズが大きくなります。復元すると現在の主要データは置き換わるため、先に現在データを書き出してください。通知権限は端末固有なのでバックアップせず、復元後の食材と通知設定から通知予約だけを作り直します。

## 主なデータの場所

`FoodItem`は`src/types/index.ts`にあり、次の値を持ちます。

```ts
type FoodItem = {
  id: string;
  name: string;
  productName: string | null;
  ingredientName: string;
  image: string;
  category: 'vegetables' | 'meat' | 'seafood' | 'dairy' | 'eggs' | 'staples' | 'seasonings' | 'beverages' | 'other';
  tags: string[];
  storage: 'refrigerated' | 'frozen' | 'room';
  quantity: number;
  quantityUnit: 'piece' | 'g' | 'ml' | 'bottle' | 'bag' | 'pack';
  expiryDate: string;
  purchaseDate: string;
  memo: string;
  createdAt: string;
  status: 'active' | 'used' | 'disposed';
  usedAt: string | null;
  disposedAt: string | null;
};
```

`name`はこれまで通りの表示名です。バーコード商品では`productName`に正式な商品名、`ingredientName`にレシピ判定で使う一般的な食材名を保存します。画面表示は`productName`があれば優先し、レシピ判定は`ingredientName`と明示した表記ゆれを使います。`tags`はホーム検索に使います。

日付は`YYYY-MM-DD`形式です。以前から保存されている食材に`status`、`productName`、`ingredientName`、`tags`、`quantityUnit`がない場合は、読み込み時に自動補完します。端末保存のキーと処理は`src/services/storage.ts`、既存データの補完は`src/context/AppDataContext.tsx`にまとめています。

## 使い切り・廃棄記録の確認

1. 食材カードを普通にタップし、これまで通り詳細画面が開くことを確認する
2. 詳細画面の「使い切った」を押し、確認で「記録だけ」を選ぶとホームから消えることを確認する
3. 別の食材で「捨てた」も同様に確認する
4. 確認画面で「キャンセル」を押した場合は、ホームに食材が残ることを確認する
5. ホームのカードを右へしっかりスワイプし、ボタンを押さずに「捨てた」の確認が開くことを確認する
6. ホームのカードを左へしっかりスワイプし、ボタンを押さずに「使い切った」の確認が開くことを確認する
7. 「買い物リストにも追加」を選ぶと、記録後に未完了の買い物リストへ同じ食材が追加されることを確認する
8. 同じ食材が未完了の買い物リストにある場合は、重複して追加されないことを確認する
9. カレンダーを開き、記録済みの食材が日付ラベルと近日予定から消えることを確認する
10. 設定の「食材ロス統計」を開き、今月の2種類の件数とロス率を確認する
11. ロス率が `捨てた数 ÷ (使い切った数 + 捨てた数) × 100` になり、記録0件では`0.0%`になることを確認する
12. 統計の「取り消す」で管理中へ戻り、ホームとカレンダーへ再表示されることを確認する
13. Expo Goを閉じて開き直し、記録状態と統計が残っていることを確認する

「削除する」は履歴に残らない完全削除です。間違えて登録したデータだけに使用します。「捨てた」は赤色にし、スワイプ完了だけでは記録を確定せず、必ず確認ダイアログを表示します。スワイプ操作の説明は初回だけ表示され、「OK」を押すと端末内に確認済みとして保存されます。

## 買い物リストの確認

1. 買い物リストで、未購入の「買うもの」が先に表示されることを確認する
2. 「よく買うもの」を開き、候補から追加できることを確認する
3. 同名の食材を入力し、重複せず「すでに買うものにあります」と表示されることを確認する
4. チェックだけで購入済みになり、別画面へ移動しないことを確認する
5. 「購入済み」を開き、「食材を登録」から食材名とメモが引き継がれることを確認する。購入量はフォームで指定する
6. 購入済みのチェックを外すと未購入へ戻ることを確認する
7. ごみ箱を押した後、キャンセルなら残り、「削除する」で削除されることを確認する
